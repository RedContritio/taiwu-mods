# 太吾必孕妙法 FertilityControl

太吾参与的生育参数指定 Mod。

除下方“不能控制的地方”外，太吾参与的发生关系和怀孕判定链路中，相关参数都可以通过设置直接指定。所有功能开关默认关闭，“谁来怀孕”默认保持正式版“原生母方怀孕”规则。

## 可以指定的内容

| 内容 | 范围 |
|------|------|
| 谁来怀孕 | 原生父方怀孕 / 原生母方怀孕 / 固定太吾怀孕 / 固定对方怀孕 |
| 父方生育能力 | 0-15000 |
| 母方生育能力 | 0-15000 |
| 必定怀孕 | 开/关（开 = 100% 必定怀孕）|
| 允许同性生育 | 开/关 |
| 是否忽略子嗣数量上限 | 开/关 |
| 必定生蛐蛐 | 开/关（开 = 新怀孕必出蛐蛐）|
| 近亲不会畸形 | 开/关 |

怀孕状态实际挂在最终的“母方”参数上。本 Mod 的怀孕承载者设置会在正式版完成父方/母方分配后重排这两个参数：选择“原生父方怀孕”时，正式版原本的父方会成为实际怀孕者；选择“固定太吾怀孕”或“固定对方怀孕”时，会把对应角色放到实际怀孕者位置。

父方/母方生育能力位于“进阶设置”分组，仍只影响原生生育力公式和子嗣数量上限。若开启“必定怀孕”，怀孕判定必定成功（100%），不再经由父方/母方生育能力相乘，且无视生育力为 0；子嗣数量上限仍由“忽略子嗣数量上限”控制。

## 不能控制的地方

| 不能控制的地方 | 说明 |
|----------------|------|
| 主动触发发生关系 | 本 Mod 不会新增事件，也不会提高进入发生关系流程的机会；必须由游戏原本流程先尝试进入发生关系或怀孕判定 |
| 非太吾组合 | 太吾不参与的 NPC-NPC 生育不受影响 |
| 未进入怀孕链路的流程 | 如果正式版某个场景在调用怀孕判定前就直接跳过，本 Mod 不会额外补一次怀孕尝试 |
| 已孕状态 | 最终怀孕承载者已经怀孕时，仍会被正式版已孕检查阻止 |
| 怀孕锁定期 | 最终怀孕承载者处于分娩后的怀孕锁定期时，仍会阻止再次怀孕 |
| 后续称谓和文本 | 怀孕状态、密闻、提示文本仍使用正式版父方/母方语义；若选择父方怀孕，文本不会被本 Mod 重写成新称谓 |
| 已有怀孕状态 | 必定生蛐蛐只改新建的太吾参与怀孕状态，不会回头改已有怀孕 |
| 生育之外的副作用 | 关系、经历、密闻等正式版后续副作用不由本 Mod 重新设计 |

## 设置

| 设置 | 分组 | 类型 | 默认值 | 范围 |
|------|------|------|--------|------|
| 谁来怀孕 | 基础设置 | 下拉 | 原生母方怀孕 | 原生父方怀孕 / 原生母方怀孕 / 固定太吾怀孕 / 固定对方怀孕 |
| 必定怀孕 | 基础设置 | 开关 | 关 | - |
| 允许同性生育 | 基础设置 | 开关 | 关 | - |
| 忽略子嗣数量上限 | 基础设置 | 开关 | 关 | - |
| 必定生蛐蛐 | 基础设置 | 开关 | 关 | - |
| 近亲不会畸形 | 基础设置 | 开关 | 关 | - |
| 指定父方生育能力 | 进阶设置 | 开关 | 关 | - |
| 父方生育能力值 | 进阶设置 | 滑块 | 100 | 0-15000 |
| 指定母方生育能力 | 进阶设置 | 开关 | 关 | - |
| 母方生育能力值 | 进阶设置 | 滑块 | 100 | 0-15000 |

“允许同性生育”控制正式版最前面的角色组合门槛。关闭时，男男、女女等正式版无法分配父方/母方的组合仍会失败；开启后，这些组合可以进入后续怀孕判定。“谁来怀孕”设置只决定谁作为实际怀孕者，不会单独放行非原生组合。

## 技术信息

纯后端 Mod，ModId、程序集名和目录名保持为 `FertilityControl`，游戏内显示名为“太吾必孕妙法”。

Harmony 补丁目标：

| 目标 | 用途 |
|------|------|
| `Character.GetMakeLoveRole` | 允许非原生组合通过角色分配门槛，并按设置重排怀孕承载者 |
| `Character.CheckMakeLoveRole` | 允许重排后的父方/母方组合通过合法性检查 |
| `PregnantState.CheckPregnant` | 指定生育力、必定怀孕和子嗣数量上限 |
| `CharacterDomain.CreatePregnantState` | 必定蛐蛐（新怀孕状态强制产出蛐蛐）|
| `CharacterDomain.IsInsect` | 禁止太吾参与的近亲畸形 |
